# پروژهٔ ارزیابی و درسنامهٔ ریاضی ۱ دهم

این سند اصول فنی و آموزشیِ پروژه را شرح می‌دهد: ساختار فایل‌ها، شیوهٔ بارگذاری، جای ماژول‌ها، قراردادهای ظاهری و تعاملی و معیارهای نمایش روی گوشی. هر بخش توصیف می‌کند که پروژه چگونه کار می‌کند و چرا؛ بنابراین خواندنش برای افزودن درس، سؤال یا ماژول تازه کافی است.

## صفحه‌ها

| صفحه | آدرس |
|---|---|
| منوی اصلی | `index.html` |
| آزمون فصل N | `chapters/chapter.html?ch=N` |
| درسنامهٔ فصل N | `courses/course.html?ch=N` (و `#sk-<id>` برای باز کردن یک مهارت) |

`chapters/chapterN.html` و `courses/courseN.html` فقط ریدایرکت‌اند و منطقی ندارند.

## ساختار

```
data/chN.js              ← منبع مشترک هر فصل: meta, skills (prereq/external/desc), count, ready
data/chapter-info.js     ← توضیح کوتاه هر فصل (برای «بخش …» در گزارش)
chapters/
  chapter.html           ← صفحهٔ آزمون (همهٔ فصل‌ها)
  js/loader.js           ← لودر مشترک (Loader.load / Loader.ordered)
  js/exam-setup.js       ← آماده‌سازی صفحه از data/chN.js
  js/app.js              ← هستهٔ آزمون
  js/math.js             ← رندر ریاضی (MathLite): تبدیل $...$ به KaTeX و ارقام فارسی
  js/report.js           ← ساخت گزارش؛ فقط هنگام «اتمام آزمون» لود می‌شود
  js/report-katex.js     ← فونت‌های KaTeX به‌صورت base64 برای فایل نتیجهٔ آفلاین؛ هم‌زمان با گزارش لود می‌شود
  js/questions-chapterN.js ← فقط ERR_NAMES و QUESTIONS
  js/heroes.js           ← تصویر بالای صفحهٔ هر فصل (آزمون و درسنامه)
  js/menu.js             ← منوی اصلی؛ فقط data/chN.js را می‌خواند و KaTeX را با باز شدن پنجرهٔ مبحث‌ها لود می‌کند
courses/
  course.html, js/core.js ← پوستهٔ درسنامه و لودر درس‌ها و ماژول‌ها
  js/mathfit.js           ← شکستن خودکار فرمول‌های نمایشی بلند روی صفحهٔ باریک
  js/shared/*.js          ← ماژول‌های مشترکِ چند درس (کدشان فقط وقتی لود می‌شود که درسی بخواهدشان)
  lessons/chN/<id>.js     ← هر درس و تمرین‌های اختصاصی‌اش
  css/*.css               ← استایل‌ها؛ بخش «CSS» را ببینید
tools/sync-data.js       ← به‌روزرسانی خودکار count و ready در data/chN.js
```

## بارگذاری و جای کد

### چه چیزی تنبل (lazy) لود می‌شود
- **درس‌ها:** `core.js` فایل یک درس را فقط وقتی مهارتش باز شود می‌گیرد (`lessons/chN/<id>.js`).
- **ماژول‌های مشترک:** هر درس در `needs` فهرست ماژول‌های موردنیازش را می‌دهد و `MODULES` در `core.js` وابستگی‌های آن‌ها را به ترتیب لود می‌کند (`coord` به `kit`، و `kit` به `utils` و `inputs` وابسته است). ماژولی که هیچ درس بازشده‌ای نخواهدش، لود نمی‌شود.
- **گزارش آزمون و فونت‌های base64 KaTeX:** فقط هنگام پایان آزمون.
- **KaTeX در منو:** فقط وقتی پنجرهٔ مبحث‌ها باز شود.
- **ثابت و غیرتنبل:** فایل‌های CSS (با `<link>`ی ثابت)، `loader.js`، `katex.min.js`، `math.js`، `core.js` و `mathfit.js` که کوچک است و باید روی هر فرمولِ هر درس اثر بگذارد.

### کد مشترک یا کد مخصوص یک درس؟
- کدی که **دو درس یا بیشتر** به همان شکل لازم دارند در `courses/js/shared/` می‌رود و با یک خط در `MODULES` (همراه `needs`ش) معرفی می‌شود.
- کدی که فقط به یک درس معنا می‌دهد (تمرین اختصاصی، داده‌های همان درس، منطق ویژهٔ آن) داخل فایل همان درس می‌ماند. کپی‌شدن یک تابع در سه درس نشانهٔ آن است که زمان انتقالش به ماژول مشترک رسیده؛ مشترک‌شدنِ زودهنگام، کدی را که هنوز دو مصرف‌کننده ندارد به ماژولی که همه می‌بینند اضافه می‌کند.
- ماژول مشترک خروجی ثابت دارد: تابعی که ابزارِ محلیِ درس (`K`) را می‌گیرد و شیء ابزار را برمی‌گرداند (مثل `K0.lk(K)` و `K0.cd(K)`). ماژول‌های مشترک استایل خودشان را در فایل CSS می‌گذارند، نه با تزریق از جاوااسکریپت.
- نام‌ها و امضاهای ماژول‌های موجود توسط چند درس استفاده می‌شوند؛ تغییرشان یعنی بازبینی همهٔ مصرف‌کنندگان.

### قرارداد درس
- فایل درس در `courses/lessons/chN/<id>.js` است و شناسه‌اش با `data/chN.js` سازگار.
- `needs` فقط ماژول‌هایی را دارد که درس واقعاً استفاده می‌کند.
- `setup(K0)` شیء `{html, init}` برمی‌گرداند: `html` ساختار محتوا را می‌سازد و `init` پس از قرارگرفتن HTML در صفحه تعامل‌ها را راه می‌اندازد.
- اجزای تعاملی، کلاس‌ها و رندر ریاضی از قواعد همین سند پیروی می‌کنند؛ ساختار یک درس دیگر مرجع طراحی نیست.
- بعد از افزودن درس یا سؤال `node tools/sync-data.js` وضعیت `ready` و `count` را به‌روز می‌کند. (در پروژه‌های بزرگ‌تر می‌توان آن را با hook پیش از commit — `node tools/sync-data.js && git add data/` — یا با `node --watch-path=chapters/js --watch-path=courses/lessons tools/sync-data.js` خودکار کرد.)

### کارهای رایج
- **سؤال جدید:** در `questions-chapterN.js` اضافه می‌شود، سپس `sync-data`.
- **مهارت یا توضیح تازه:** فقط `data/chN.js` ویرایش می‌شود؛ منو، آزمون و درسنامه هر سه از همان می‌خوانند.

## CSS

استایل‌ها در چند فایل CSS معمولی‌اند (نه ماژول و نه تنبل) که با `<link>` و به ترتیب ثابت لود می‌شوند. تفکیک فایل‌ها برای خوانایی است و دامنهٔ انتخابگرها را محدود نمی‌کند.

| فایل | مسئولیت |
|---|---|
| `chapters/css/katex.min.css` | ظاهر فرمول‌ها (درسنامه هم از آن استفاده می‌کند) |
| `chapters/css/style.css` | پوسته و اجزای مشترکِ آزمون و درسنامه |
| `courses/css/course-base.css` | شالودهٔ درسنامه: متغیرهای رنگ، سربرگ، چیدمان پایه، اجزای عمومی |
| `ch2.css` | عبارت‌های جبری و ابزارهای تعاملی جبر؛ بعضی قواعدش بر استایل‌های پیشین تقدم دارند |
| `ch1.css` | کنترل‌ها و فعالیت‌های عدد و کسر؛ بعضی انتخابگرهایش عمومی‌اند |
| `course-shared-overrides.css` | فقط قواعد واقعاً بین‌فصلی که قبلاً در این فایل بودند (`.stg`، دکمه‌های قبلی/بعدی، `.end-actions`، `.ask`…). قواعد مخصوص هر فصل به `chN.css` همان فصل رفته‌اند |
| `ch3.css` | درس‌های معادله و فعالیت‌هایشان |
| `ch7.css` | فعالیت‌های فصل هفتم (انتخابگرهای محدود به `.p7-act`) |
| `ch5.css` | استایل مشترک هندسه (انتخابگرهای محدود به `.g5-scope`) |
| `ch4.css` | صفحهٔ مختصات، جدول داده، ورودی زوج مرتب، بازی‌ها و آزمونِ ماژول `coord` |
| `ch6.css` | استایل اختصاصی درس‌هایی از فصل ششم که قاعدهٔ مخصوص دارند |

هر `chN.css` فقط قواعد اختصاصی همان فصل را دارد. قاعده‌هایی که فصل‌های دیگر هم از آن‌ها استفاده می‌کنند (مثل `.mc .opt`، `.lesson-bridge*`، `.graduated-*`) در فایل‌های `course-shared-chN.css` و `course-shared-overrides.css` مانده‌اند؛ این فایل‌ها عمداً جدا از هم نگه داشته شده‌اند تا ترتیب cascade همان ترتیب قبلی بماند.

### ترتیب بارگذاری در `courses/course.html`
```
katex.min.css -> style.css -> course-base.css -> (به ترتیب ORDER در course.html) course-shared-ch2 -> ch2* -> course-shared-ch1 -> ch1* -> course-shared-overrides -> course-shared-ch3 -> ch3* -> course-shared-ch7 -> ch7* -> course-shared-ch5 -> ch5* -> course-shared-ch4 -> ch4* -> ch6*
```
(*) فقط CSS همان فصلی که با `?ch=N` باز شده لود می‌شود؛ بقیهٔ فصل‌ها لود نمی‌شوند. همهٔ CSS هنگام ورود به صفحه و یک‌جا لود می‌شود (lazy نیست)؛ lazy-load فقط برای JS درس‌هاست.

### قواعد نوشتن استایل
1. اجزای مشترک اول در `style.css`، `course-base.css` و `course-shared-overrides.css` جست‌وجو می‌شوند تا تعریف تکراری ساخته نشود.
2. استایل فعالیت اختصاصی در فایل همان فصل می‌آید و انتخابگرها زیر کلاس ریشهٔ همان درس/فصل محدود می‌شوند.
3. کلاس‌های عمومی (`.btn`، `.opt`، `.ch`، `.infobtn` …) در چند فصل استفاده می‌شوند؛ اصلاح موردی با انتخابگر محدود به همان فعالیت انجام می‌شود.
4. هنگام انتقال قواعد، محتوای `@media`، ترتیب قاعده‌ها و مسیر `url(...)` (که نسبت به خود فایل CSS تفسیر می‌شود) حفظ می‌شود.
5. پس از تغییر، درس‌های مرتبط و دست‌کم یک نمونه از فصل‌های دیگر در دسکتاپ و عرض‌های ۳۲۰ و ۳۶۰ دیده می‌شود؛ درست‌بودن نحو CSS یکسانی ظاهر را تضمین نمی‌کند.

## اصول طراحی آموزشی

### کادر پیوند آموزشی (اختیاری)
کادر پیوند آموزشی ارتباط درس جدید با آموخته‌های پیشین را نشان می‌دهد. حالت پیش‌فرض نبودن آن است و حضورش توجیه آموزشی می‌خواهد.

**معیار:** وقتی افزوده می‌شود که (۱) درس ارتباط مفهومی مهمی با آموخته‌های قبلی دارد که برای دانش‌آموز آشکار نیست، (۲) نشان‌دادنش به درک بهتر یا جلوگیری از سوءبرداشت کمک می‌کند و (۳) مقدمهٔ درس همین ارتباط را روشن نکرده است. اگر مقدمه همین کارکرد را دارد، کادر تکراری ساخته نمی‌شود (مقدمه و کادر یکی می‌شوند).

**موقعیت‌های مناسب:** پیوند چند آموختهٔ پیشین، تغییر زاویهٔ نگاه به مفهومی که قبلاً آموخته شده، و گذار مفهومی به شیوهٔ تازه‌ای از استدلال. وجود پیش‌نیاز یا شباهت موضوعی به‌تنهایی دلیل کافی نیست.

**محتوا و ظاهر:**
- کوتاه و روشن، با عنوانی اختصاصی و دو تا چهار جملهٔ هدفمند دربارهٔ ارتباط مفاهیم و چرایی یادگیری؛ نه تکرار تعریف یا فهرست هدف.
- بعد از معرفی کوتاه و پیش از آموزش اصلی می‌آید؛ با هویت بصری پروژه هماهنگ است ولی شکل ارائه (مسیر مفهومی، مقایسه، پرسش، مثال) به موضوع بستگی دارد.
- عنوان به محتوای همان درس بستگی دارد (عنوان ثابت ندارد).
- ارجاع به درس‌ها با نام طبیعی مفهوم است؛ شناسه‌های فنی مثل `N01` در متن دانش‌آموز دیده نمی‌شوند.
- انتهای کادر مسیر یادگیری را با برچسب‌های کوتاه و پیکان نشان می‌دهد.

### آزمون پایانی
آخرین فعالیت ارزشیابی هر درس «آزمون پایانی» نام دارد و پرسش‌هایش با اهداف درس هم‌راستاست. اگر بعد از آن جمع‌بندی (مثل «بعد از این درس باید بتوانی») می‌آید، آزمون پایانی همچنان آخرین فعالیت تعاملی است.

## استاندارد اجزای تعاملی

هر قاعدهٔ این بخش دربارهٔ اجزای **هم‌نقش** است؛ هدف یکسانیِ رفتار هم‌کارکردهاست، نه یک‌شکل‌شدن همهٔ دکمه‌ها. استثنا با دلیل آموزشی یا تعاملی روشن ممکن است.

### نقش اجزا

| جزء | قابل کلیک؟ | جهت چیدمان | پیش‌فرض و رفتار |
|---|---|---|---|
| نوار پیشرفت سؤال‌ها یا مرحله‌ها (دایره‌های شماره‌دار یا عنوان متنی) | خیر | همیشه راست به چپ | اولین مورد سمت راست؛ فقط مورد جاری برجسته؛ جابه‌جایی فقط با کنترل ناوبری |
| دکمه‌های انتخاب مقدار عددی | بله | چپ به راست | پیش‌فرض در سمت راست گروه، مگر مقدار اولیهٔ مسئله چیز دیگری بخواهد |
| دکمه‌های انتخاب حالت با برچسب فارسی | بله | راست به چپ | دکمهٔ سمت راست پیش‌فرض، مگر منطق آموزشی چیز دیگری بخواهد |
| گزینه‌های پاسخ | بله | متناسب با نوع پاسخ | عددی‌بودن گزینه، آن را نوار پیشرفت نمی‌کند؛ پاسخ پیش‌فرض انتخاب‌شده نیست |

نوار پیشرفت با کلیک روی شماره سؤال را عوض نمی‌کند و حالت Hover شبیه دکمه ندارد. در انتخاب حالت، وضعیت انتخاب‌شده تا انتخاب بعدی پایدار است و Hover آن را عوض نمی‌کند.

### رنگ، اندازه و متن دکمه
- **سفید:** عملیات معمولی (بررسی، برگردان، سؤال قبلی)، تغییر مقدار و گزینهٔ بی‌پاسخ.
- **زرد:** وضعیت انتخاب‌شدهٔ گروه حالت، تب یا شمارهٔ مرحلهٔ جاری؛ نشانهٔ درستی پاسخ نیست.
- **سبز:** دکمهٔ رفتن جلو یا عوض‌کردن نمونه («سؤال بعدی»، «مثال بعدی»، «عدد دیگر»، «مسئلهٔ دیگر»، «نمونه‌های تازه»، شروع) و تأیید/نتیجهٔ درست. در هر ردیف دکمهٔ سبز سمت چپ و بقیه سمت راست است (در DOM دکمهٔ سبز آخر می‌آید).
- **خاکستری:** غیرفعال یا انتخاب‌نشده؛ کنتراست متن حفظ می‌شود و رنگ به‌تنهایی وضعیت را نمی‌رساند.
- در هر گروه هم‌کارکرد ارتفاع، فونت، ضخامت حاشیه، گردی گوشه، فاصلهٔ داخلی و سایه یکسان است. عرض گزینه‌های متنی به محتوا بستگی دارد و دکمه‌های هم‌گروهِ غیرضروری تمام عرض کادر را نمی‌گیرند. گروه‌های عددی کوتاه یک‌اندازه‌اند (در صورت لزوم دایره‌ای)؛ گزینه‌های متن فارسی کپسولی‌اند.
- برچسب‌ها عمل واقعی را می‌گویند: «مرحلهٔ بعدی» برای مرحلهٔ یک فعالیت؛ «سؤال قبلی/سؤال بعدی» برای ناوبری سؤال؛ «عدد دیگر»، «جدول دیگر»، «دیوار دیگر» و «مسئلهٔ دیگر» برای نمونهٔ مستقل؛ «برگردان» و «بازنشانی» فقط برای بازگردانی وضعیت.
- **سایه و افکت:** دکمه‌های عملیاتی سفید و کنترل‌های انتخاب وضعیت سایهٔ هماهنگ و افکت فشردن ملایم (`translate(1px,1px)` با کاهش سایه) دارند و رنگ انتخاب‌شده پس از رهاکردن می‌ماند. دکمهٔ سبزِ «نمونهٔ دیگر» و دکمهٔ سفیدِ «بررسی» کنار هم سایه یا جابه‌جایی ندارند. دو دکمهٔ کنترلیِ هم‌ارز (مثل «▶ تا کن» و «◀ برگردان») هر دو سفید و دورمشکی با سایه و افکت فشردن‌اند و آیکن‌هایشان قرینه است. دکمه‌های سبز ادامه، ناوبری سؤال‌ها و گزینه‌های پاسخ بدون افکت حرکت‌اند و رنگ و حاشیه‌شان وضعیت را می‌گوید. افکت یا سایه به کل `.btn` یا `.btn.primary` اعمال نمی‌شود؛ حالت‌های `disabled`، `:focus-visible` و `prefers-reduced-motion` رعایت می‌شوند.

### نوار پیشرفت و ناوبری سؤال
- تمرینی که نوار پیشرفت دارد، آن را با ترتیب راست‌به‌چپ نگه می‌دارد؛ تمرینی که ندارد، صرفاً برای یکسانی نوار نمی‌گیرد. تمرین تازه فقط در صورتی نوار دارد که ساختارش بخواهد.
- «سؤال قبلی» سمت راست و «سؤال بعدی» سمت چپ است؛ در ابتدا و انتها disabled واضح است.
- پاسخ‌های ثبت‌شده با بازگشت به سؤال قبلی می‌مانند و امتیاز با رفت‌وبرگشت یا کلیک مکرر دوباره شمرده نمی‌شود.
- پیام موفقیت یا شکست پیش از اقدام دانش‌آموز نمایش داده نمی‌شود؛ بازخورد اشتباه آموزشی است و پاسخ سؤال‌های بعدی را لو نمی‌دهد.
- سؤال با سه گزینهٔ متنی به‌طور پیش‌فرض چیدمان عمودی، وسط‌چین و با عرض محدود دارد، مگر ساختار آموزشی چیز دیگری بخواهد.
- در نوار عددی، شمارهٔ سؤال جاری در خود نوار است و پیشوند تکراری «سؤال ۱ از ۵:» در متن نمی‌آید. نوار متنی نام مرحله را می‌دهد و زیرش در صورت نیاز اطلاعات کوتاهی مثل «مرحلهٔ ۱ — سؤال ۱ از ۲» می‌آید (قفل «تعداد پاسخ درست» برداشته شده است). صورت سؤال در سطر مستقل و بولد است. هیچ فعالیتی قفل «تعداد پاسخ درست» ندارد: پیشرفت فقط با «سؤال بعدی» است و هر سؤال یک بار ثبت می‌شود.
- گزینه‌های غلطِ تمرین‌های چندگزینه‌ای از خطاهای رایج دانش‌آموزان ساخته می‌شوند و هیچ‌کدام نباید با پاسخ برابر یا از نظر ریاضی هم‌ارز آن باشد، یا با گزینهٔ دیگری تکراری شود؛ به فیلتر تکرار در کد تکیه نمی‌شود و بازهٔ عددهای تصادفی طوری انتخاب می‌شود که این حالت‌ها پیش نیاید. عبارت‌های جبری بدون جملهٔ صفر و بدون ضریب ۱ نوشته می‌شوند (`x^2-9` نه `x^2+0x-9`).

**اندازهٔ مبنای فونت (واحد `rem` نسبت به فونت ریشه):**

| نقش | اندازه | وزن |
|---|---|---|
| صورت سؤال و دستور اصلی | `1rem` | ۷۰۰ |
| عنوان یا شمارندهٔ مرحله در سطر مستقل | `0.85rem` | ۴۰۰ |
| برچسب‌های نوار پیشرفت | `0.88rem` | بر حسب وضعیت |
| گزینهٔ پاسخ متنی | `1rem` | ۴۰۰ |
| گزینهٔ پاسخ عددی | `1.15rem` | معمولی |
| متن بازخورد (`.fb`) | `1rem` | معمولی (تأکید مجاز) |
| متن توضیح و راه‌حل (`.ex`) | `1rem` | معمولی |
| دکمه‌های ناوبری | `0.9rem` | ۷۰۰ |
| دکمه‌های عمل در کارگاه‌ها (بررسی، نمونهٔ دیگر، اجرا) | `0.88rem` تا `0.9rem`، حداقل عرض `120px`، حداقل ارتفاع `36px` | ۷۰۰ |

نکته: کلاس‌های ظرف مثل `.n3-w`، `.n6-w` و `.n9-w` فونت ظرف را `.95em` می‌کنند؛ برای همین `.fb` و `.ex` در آن‌ها صریحاً `1rem` گرفته‌اند. ظرف جدید نباید فونت کادر پیام را کوچک کند.

این جدول هماهنگی هم‌نقش‌ها را مشخص می‌کند و اندازهٔ کسر و رادیکال و فرمول بلند را یکسان نمی‌کند؛ تایپ‌ست KaTeX، فونت فارسی، فضای عمودی و عرض گزینه در هر درس جدا بررسی می‌شود.

### پایان فعالیت‌های چندسؤالی
- فعالیت چندسؤالی‌ای که مرور پاسخ‌ها و دور تازه دارد، در صفحهٔ نتیجه دو دکمه با همین متن دارد: «مرور سؤال‌ها» (راست) و «سؤال‌های جدید» (چپ). بازگشت، همان سؤال‌ها و پاسخ‌های ثبت‌شده را نشان می‌دهد و دور تازه مجموعه را بازسازی می‌کند.
- دکمهٔ رفتن از آخرین سؤال به نتیجه «مشاهدهٔ نتیجه» نام دارد.
- دو دکمهٔ صفحهٔ نتیجه در یک ردیف راست‌به‌چپ، با ارتفاع و فونت و حداقل عرض یکسان‌اند و سایه یا جابه‌جایی ندارند.
- فعالیت چندسؤالی (از جمله مرحله‌ای) همیشه مرور دارد. فقط فعالیتی که پاسخ ثبت‌شده‌ای ندارد (کارگاه آزاد) دکمهٔ مرور صوری نمی‌گیرد.
- متن و ساختار صفحهٔ نتیجه در همه‌جا یکی است و فقط از `K.res(امتیاز, تعداد)` در `core.js` ساخته می‌شود (کادر `.fb` با `<b>نتیجه: x از y</b>`، یک `<br>` و یک جمله). سه حالت: همه درست («عالی بود! همهٔ سؤال‌ها را درست حل کردی.»)، حداکثر دو اشتباه («خوب بود. سؤال‌هایی را که اشتباه کردی مرور کن.») و بیشتر («یک بار دیگر درس را مرور کن؛ بعد با سؤال‌های جدید امتحان کن.»). کادر برای حالت اول و دوم سبز و برای سوم قرمز است. متن اختصاصی هر درس برای نتیجه نوشته نمی‌شود. هر دو خط یک فونت دارند و فقط خط اول بولد است.
- شرط پایان فعالیت‌های محدود مستقل از شمار پاسخ‌های درست است و شمار درست‌ها جدا برای گزارش ثبت می‌شود تا پاسخ غلط به ادامهٔ بی‌پایان نینجامد.
- تمرین «سه دروازهٔ کسر» (A08) هم همین آزمون استاندارد است: سه سؤال، «سؤال قبلی/بعدی»، «مشاهدهٔ نتیجه» و صفحهٔ نتیجه.
- تمرین‌های مرحله‌ایِ فصل ۱ (N01 `steps`، N02 `fracSteps`، N04 `cmpSteps`، N05 `scaleRead` و `placer`، N07 `rootSteps`، N08 `absSteps`، N10 `gcmSteps`) مجموعهٔ ثابت سؤال دارند (هر مرحله ۲ سؤال) و هر سؤال یک بار ثبت می‌شود. «سؤال قبلی»، «سؤال بعدی»، «مشاهدهٔ نتیجه» و صفحهٔ نتیجه با «مرور سؤال‌ها» و «سؤال‌های جدید» دارند. موتور مشترک آن‌ها `H.stages` در `lessonkit.js` است (ماژول `kit`، چندگزینه‌ای یا با ورودی نوشتاری)؛ فقط `placer` چون تعاملی است منطق خودش را دارد. در سؤال کسری، جواب درست ولی ساده‌نشده شمرده نمی‌شود و بدون ثبت دوباره پرسیده می‌شود.
- قاعدهٔ ردیف دکمه‌های عمل در کارگاه‌ها: دکمهٔ سبز (مثال/سؤال بعدی، شروع) سمت چپ و «بررسی» و بقیه سمت راست؛ یعنی در DOM دکمهٔ سبز آخر می‌آید. ردیف سه‌دکمه‌ای (N03، N04) `flex-wrap:nowrap` دارد تا شکسته نشود.
- `normalizeFeedback` در `core.js` تیک ✓ ابتدای `.fb.ok` را در `span.quiz44-tick` (سبز تیره `#0a6f61`) می‌گذارد، تیکِ انتهای جمله را به ابتدا می‌آورد و هر ✓ و ✗ داخل `.fb` و `.ex` را با `colorMarks` سبز یا قرمز تیره (`.quiz44-tick` و `.quiz44-cross`) می‌کند. تیک و ضربدرِ نوشته‌شده در جاهای دیگر (مثل ترازوها) مستقیم با همین دو کلاس نوشته می‌شود.

### بازخورد و راه‌حل
- **پاسخ درست:** کادر سبز مستقل با `✓` و پیام کوتاه و طبیعی («✓ آفرین، درست حل کردی!»)؛ پیام‌ها در همهٔ تمرین‌ها یکسان نیستند.
- **پاسخ نادرست:** کادر قرمز مستقل با بازخورد آموزشی؛ در تمرین‌های قابل‌تکرار فقط راهنمایی می‌دهد و پاسخ نهایی را زود آشکار نمی‌کند.
- **کادرها:** پیام فقط با `div.fb` (نه `p.fb`) و توضیح فقط با `div.ex` ساخته می‌شود؛ کلاس سفارشی برای کادر پیام یا توضیح نمی‌سازیم. پیام کوتاه در `.fb` و بقیه در `.ex` می‌آید. پیام درست/نادرست در آزمون‌های «درست یا نادرست» «پاسخ نادرست است.» است.
- **توضیح و محاسبه:** در کادر مستقل با حاشیهٔ نقطه‌چین، زیر کادر بازخورد، و فقط وقتی که نمایش راه‌حل مجاز است (پس از پاسخ یا پایان تلاش‌ها).
- **گزینه‌های قطعی‌شده:** پس از ثبت پاسخ قطعی، گزینهٔ درست زمینهٔ سبز کم‌رنگ و گزینهٔ غلطِ انتخاب‌شده زمینهٔ قرمز کم‌رنگ دارد؛ بقیه خنثی‌اند، قفل‌شدن آن‌ها را کم‌رنگ نمی‌کند و Hover هم ندارند (حاشیهٔ آن‌ها با ‎`:hover`‎ عوض نمی‌شود). در مرور پاسخ‌ها هم همین نمایش می‌ماند. تا پیش از قطعی‌شدن، رنگ یا نشانه‌ای پاسخ درست را آشکار نمی‌کند.
- **دکمهٔ نمونهٔ تازه** بعد از پیام موفقیت و توضیحش می‌آید.

## ریاضی و متن فارسی

- نمادها و عددهای ریاضی، به‌ویژه در دکمه‌ها، با KaTeX (از طریق رندرگر مشترک `MathLite`) نمایش داده می‌شوند؛ دستور خام مثل `\times` یا رشتهٔ ترکیبیِ خراب نمایش داده نمی‌شود. در شکل‌های SVG ارقام فارسی با همان تابع تبدیل نوشته می‌شوند.
- جملهٔ معرفی محاسبه با `:` تمام می‌شود، محاسبه در خطی مستقل و وسط‌چین است و توضیح بعدی در خط بعد. عبارت کوچک و مستقلی که بخشی از جمله است (`x=3`، یک عدد) در متن می‌ماند.
- زنجیرهٔ محاسبات پیوسته ترجیحاً در یک خطِ نمایشی است و فقط با کمبود واقعی فضا چندخطی می‌شود. روی صفحهٔ باریک این شکستن خودکار است (بخش «موبایل»). شکستن معنادار و خوانا است و فرمول با `overflow:hidden` بریده نمی‌شود.
- متن فارسی داخل فرمول با روش آزموده‌شدهٔ RTL یا بیرون از KaTeX نوشته می‌شود تا ترتیب وارونه نشود؛ جای `:` و `=` در هم‌نشینی RTL/LTR در مرورگر تأیید می‌شود. متن فارسی داخل KaTeX (مثل `\text{مثلاً}` در فرمول نمایشی) به‌هم می‌ریزد و کنارش می‌آید.
- در نسبت‌ها فاصلهٔ دو سوی تساوی خوانا و معنادار است و دستورهای درشت‌فاصله مثل `\quad` به‌دلخواه جایگزین نمی‌شوند.
- اعشار با «٫» و کسر با خط کسر نوشته می‌شود؛ «/» جداکنندهٔ اعشار نیست.
- **جایگذاری در عبارت جبری:** مقدار متغیر با خط عمودی و زیرنویس کنار عبارت می‌آید: `{3x+5}_{|x=-2}` و زنجیرهٔ `{3x+5}_{|x=-2}=3\times(-2)+5=-1`. برای چند متغیر تابع `notation` در ماژول آزمایشگاه جایگذاری مرجع است. بک‌اسلش‌های TeX در رشتهٔ جاوااسکریپت درست escape می‌شوند.
- **عددی که کاربر وارد می‌کند:** نمایش مستقیم متن خام ورودی در جملهٔ راست‌به‌چپ ارقام و علامت منفی را وارونه یا ناهماهنگ می‌کند (مثلاً منفی در سمت راست عدد). پس ورودی کاربر هرگاه قرار است نمایش داده شود (مثل «پاسخ تو»)، از تابع نمایش مشترک عبور می‌کند که ارقام فارسی/عربی و انواع علامت منفی را یکدست می‌کند و نتیجه را با KaTeX می‌نویسد. محاسبه و مقایسه از مقدار تحلیل‌شده استفاده می‌کنند و به رندر نیازی ندارند؛ فقط خروجی نمایشی از KaTeX می‌گذرد.

## تعامل‌ها، نمودارها و انیمیشن

- Hover محورهای قابل‌انتخاب با دایرهٔ نقطه‌چینِ خاکستری نیمه‌شفاف (`rgba(20,33,61,0.08)`) و حباب مقدار نشان داده می‌شود؛ مستطیل اضافه ظاهر نمی‌شود و نشانگر Hover با نقطهٔ انتخاب‌شده اشتباه گرفته نمی‌شود.
- در تعامل دو نقطه‌ای، انتخاب نقطه فقط با اقدام مستقیم کاربر عوض می‌شود.
- فعالیت‌های متغیر (قطره، جدول، کارت بازخورد) ارتفاع یا عرض ذخیره‌شدهٔ مناسب دارند تا چیدمان با هر کلیک نپرد.
- کلیک مکرر روی دکمهٔ انیمیشن آن را گیر نمی‌اندازد؛ شروع، توقف و بازنشانی روشن است.
- وضعیت انتخاب، غیرفعال، Hover و فوکوس صفحه‌کلید از هم جدا هستند و حرکت‌های تزئینی در `prefers-reduced-motion` کم می‌شوند.
- ساختن تعامل لمسی: هر تعاملی که با موس کار می‌کند باید با لمس هم همان‌طور کار کند (رویداد `pointer` به‌جای `mouse`، و `touch-action` برای ناحیه‌های کشیدنی).

### اسکرول خودکار (`data-scroll`)
- اسکرول فقط برای دکمه‌ای اجرا می‌شود که صریحاً `data-scroll` داشته باشد؛ تشخیص با متن دکمه یا نام‌های عمومی `data-*` در کار نیست. این ویژگی به کنترل‌هایی داده می‌شود که سؤال، مرحله یا نمونهٔ قابل‌مشاهده را عوض می‌کنند: قبلی/بعدی، نمونهٔ دیگر، مرور و دور تازه. دکمهٔ ثبت پاسخ، انتخاب گزینه، کنترل‌های داخلی شکل و نمونه‌هایی که نباید صفحه را جابه‌جا کنند آن را ندارند.
- مقدار `data-scroll` انتخابگر مقصد در محدودهٔ همان فعالیت است (`data-scroll=".ask"`، یا `".stg"` وقتی شکل بالای صورت سؤال از دید می‌رود). مقصد پیش‌فرض نوار پیشرفتِ همان فعالیت و در نبودش صورت سؤال یا دستور اصلی است. مقصد نامعتبر یعنی اسکرولی نیست.
- اسکرول پس از ساخته‌شدن مقصد و به‌روزرسانی DOM انجام می‌شود. فاصلهٔ بالای مقصد ۸۰ پیکسل است و با `data-scroll-offset` برای استثناها عوض می‌شود.
- رفتار اسکرول در مرورگر برای هر ساختار متفاوت آزموده می‌شود؛ بررسی نحوی کافی نیست.

### نوار لغزنده
- بخش طی‌شدهٔ مسیر تا دستگیره سبز و بقیه خاکستری است؛ دستگیره خاکستری است، با Hover خاکستری تیره و هنگام کشیدن سبز فیروزه‌ای می‌شود. استایل‌های اختصاصیِ ناسازگار جای این الگو را نمی‌گیرند.
- درجه‌بندی اختیاری و بسته به نیاز فعالیت است؛ درجه‌ها زیر نوار هستند و مرکزشان دقیقاً با مرکز دستگیره در مقدار متناظر هم‌تراز است. بنابراین اندازهٔ ظاهری دستگیره عوض نمی‌شود؛ بزرگ‌کردن ناحیهٔ لمس با ارتفاع جعبهٔ ورودی (`min-height`) روی صفحه‌های لمسی انجام می‌شود.
- نوار لغزنده‌ای که مقدار یا سطحِ قابل‌شمارش را انتخاب می‌کند (مثل سطح بزرگ‌نمایی و مقدار معادله) درجه‌بندی با برچسب دارد؛ نوار پیشرفتِ انیمیشن (مثل «تاکردن» و «آینه») درجه‌بندی ندارد و فقط دو سر آن برچسب دارد.

### کشیدن و رها کردن
- فعالیتی که چیدن یا دسته‌بندی دارد (نردبان ترتیب در N04 و بازی دسته‌بندی در N03) هر دو راه را دارد: کشیدن (ماوس با `dragstart/drop` و لمس با `pointerdown/move/up` و آستانهٔ ۹ پیکسل) و انتخاب با کلیک. کارت‌ها `touch-action:none` دارند و سینی هدف هنگام کشیدن با `.over` پررنگ می‌شود. پس از کشیدنِ لمسی، کلیکِ پشت‌سرش نادیده گرفته می‌شود.

## موبایل

صفحه‌ها برای عرض ۳۲۰ تا ۴۳۰ پیکسل (و حالت افقی) طراحی می‌شوند. معیارها:

- **بدون اسکرول افقی و بدون بریدگی:** نه صفحه و نه کادر تمرین (`.cover`، پنل مهارت) محتوایی بیرون‌زده ندارد. عنصرهای شبکه‌ای (`grid`) با `minmax(0,…)` نوشته می‌شوند تا از عرض ظرف بزرگ‌تر نشوند؛ کنترل‌های ردیفی در عرض‌های ≤۴۰۰ کوچک می‌شوند یا می‌شکنند. حالت‌های حدی (بیشینهٔ لغزنده، عدد بلند، بازخورد طولانی) هم سنجیده می‌شوند، نه فقط حالت اولیه.
- **ناحیهٔ لمس:** کنترل‌های کوچک ظاهر خود را نگه می‌دارند، ولی با شبه‌عنصرِ نامرئی (`::after` با `inset` منفی) ناحیهٔ لمسی نزدیک ۴۰ تا ۴۴ پیکسل می‌گیرند (دکمهٔ «i»، دکمه‌های گرد کوچک، لینک‌های درون‌متن). دکمه‌های متنی حدود ۴۰ پیکسل ارتفاع دارند.
- **ورودی‌ها:** فونت کادرهای ورودی دست‌کم ۱۶ پیکسل است تا Safari آیفون هنگام فوکوس صفحه را زوم نکند. ورودی منفی‌پذیر کنار خود دکمهٔ تغییر علامت (±) دارد چون کیبورد عددی گوشی علامت منفی ندارد.
- **شکل‌ها (SVG):** هر شکلی که روی گوشی کوچک می‌شود باید نوشته‌ای دست‌کم حدود ۱۰ پیکسل و ترجیحاً ۱۱ تا ۱۲ پیکسل داشته باشد. راه‌ها: بزرگ‌کردن نوشته‌ها در `viewBox`، نمایش نسخهٔ فشردهٔ شکل با `@media` (و دکمه‌های لمسی به‌جای برچسب‌های ریز روی پیکان‌ها)، یا نگه‌داشتن عرض خوانا با اسکرول افقی همراه راهنمای کشیدن (مثل محور عدد). مقیاس خودکار تنها وقتی پذیرفتنی است که نوشته‌ها خوانا بمانند.
- **فرمول‌های نمایشی:** `courses/js/mathfit.js` فرمول‌های `.dm` را که از عرض بلندترند به چند خط می‌شکند: اول در جداکننده‌های صریح (`\quad`، `\qquad`)، بعد پیکان‌های استنتاج (`⇒`)، بعد رابطه‌ها (`=`، `<`، `≤` …)؛ خط‌ها هم‌اندازه می‌شوند و هر خطِ ادامه با همان نماد شروع می‌شود. فرمول‌های `aligned` سطر به سطر می‌شکنند. روی صفحهٔ عریض فرمول به یک خط برمی‌گردد. برای کار کردن، `math.js` منبع TeX فرمول‌های رابطه‌دار را در `data-tex` نگه می‌دارد. فرمولی که ساختار دیگری دارد (ماتریس، `cases`) دست‌نخورده می‌ماند و در کادر خودش اسکرول می‌شود. شکستن برای همهٔ عرض‌ها کار می‌کند و فقط فرمول‌هایی را لمس می‌کند که از ظرفشان بلندتر باشند؛ فرمول‌هایی که دستی شکسته شده‌اند تا وقتی جا شوند دست‌نخورده می‌مانند.
- **Hover و انیمیشن:** نشانگر Hover روی لمس پس از ضربه می‌ماند؛ نمایش‌دادن اطلاعات فقط با Hover یا `title` برای لمس کافی نیست و همان اطلاعات باید جای دیگری هم در دسترس باشد. انیمیشن‌های بی‌پایان کوچک و کم‌مصرف‌اند.
- **بازبینی:** بعد از تغییر، درس در عرض‌های ۳۲۰، ۳۶۰ و ۴۱۲ و حالت افقی دیده می‌شود: اسکرول افقی، بریدگی پنل و کادر، فرمول بیرون‌زده، اندازهٔ نوشتهٔ شکل‌ها، فونت ورودی‌ها و ناحیهٔ لمس. کلیک‌های تصادفی و حالت‌های حدی هم امتحان می‌شود. تست روی گوشی واقعی (Safari آیفون و کیبورد مجازی) جدا از شبیه‌ساز است و جایگزین ندارد.

## کنترل کیفیت و تحویل

1. **پیش از تغییر:** تمرین، نقش هر کنترل و الزامات روشن آموزشی/نمایشی شناسایی می‌شود.
2. **هنگام اجرا:** فقط فایل‌ها و کلاس‌های لازم تغییر می‌کنند؛ جزء مشترک وقتی به `shared` می‌رود که رفتارش در چند درس واقعاً یکسان باشد.
3. **رندر ریاضی:** فرار کاراکتر `\` در رشته‌های جاوااسکریپت و خروجی واقعی KaTeX، جهت فارسی و اندازهٔ فونت در مرورگر دیده می‌شود؛ `node --check` به‌تنهایی کافی نیست.
4. **بازبینی:** دسکتاپ و صفحهٔ باریک، RTL/LTR، سایه و حالت فشردن، پیش‌فرض سمت راست، ناوبری رو به عقب، تکرار کلیک و ماندن پاسخ‌ها.
5. **تحویل:** ZIP کامل با نام نسخهٔ بعدی، گزارش کوتاه «چه فایل‌هایی تغییر کرد» و تمایز روشن میان تست نحوی و تست واقعی در مرورگر.
